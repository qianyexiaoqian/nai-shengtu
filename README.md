# NAI 生图中继

把 NovelAI 生图转成 OpenAI 标准格式，也能原样提供 NovelAI 官方格式，带一个后台管理端。上游可以接好几个，两种都行：

- **NovelAI 官方**：用官网生成的持久令牌（`pst-...`）直接调 `image.novelai.net`；
- **OpenAI 兼容**：各家 NAI 生图站 / 中转站的 `/v1/images/generations`。

对外的接口：

| 接口 | 用途 |
| --- | --- |
| `POST /v1/chat/completions` | 香蕉生图式的聊天生图：发一句提示词，assistant 回复里带 Markdown 图片，支持 `stream`；消息里带图就是图生图 |
| `POST /v1/images/generations` | OpenAI Images 格式，补齐了 `b64_json` 等；带 `image` 就是图生图 |
| `POST /v1/images/edits` | OpenAI 图片编辑格式（multipart 传图，或 JSON），按图生图出 |
| `POST /ai/generate-image` | NovelAI 官方格式（`input` / `model` / `parameters`，返回 ZIP），给只会调 NovelAI 的客户端用，文生图和图生图 |
| `GET /user/subscription` | NovelAI 客户端连接时查的订阅信息 |
| `GET /v1/models` | 后台已启用的模型 |
| `GET /v1/img/<uuid>.png` | 返回给调用方的图片链接，由中继代拉上游图片（上游给 base64 的存在中继本地） |
| `/admin` | 后台：调用统计、上游扣点估算、调用日志、调用密钥、上游秘钥、模型、设置 |
| `/prompt` | 提词器：中文描述转标签、查标签、常用预设、关联推荐、推荐画师、试生成 |

**上面所有路径都在同一个端口上**（`PORT`，默认 3000），一个进程、一个端口，反代时整站转发到这个端口即可。

**可以直接写中文**：提示词里的中文会自动转成 NAI 认识的 Danbooru 标签，英文标签会顺便纠正拼写和旧写法（见“中文提示词”）；
还可以接一个大模型做“AI 提示词优化”，按 tokens 记成本（见“AI 提示词优化”）。

零依赖，需要 Node.js ≥ 22.9（用内置的 `node:sqlite` 存数据）。

## 启动

```bash
cp .env.example .env   # 可选，按需改端口、密码等
npm start
```

1. 首次启动会在控制台打印后台初始密码（或用环境变量 `ADMIN_PASSWORD` 指定），以及本机能访问到的地址。
2. 打开 `http://<服务器IP>:3000/admin` 登录，在“上游秘钥”页添加上游：
   - NovelAI 官方：类型选“NovelAI 官方”，贴持久令牌 `pst-...`（官网 Account Settings → Get Persistent API Token），接口地址留空；
   - OpenAI 兼容：填上游的**接口地址**（填到 `/v1`）和上游给的 `sk-...`。可以多把、可以接多个上游。
3. 在“调用密钥”页**生成本中继的调用 sk**，发给调用方。完整密钥只在生成时显示一次。
4. 调用方的基础地址填 `http://<服务器IP>:3000/v1`（不带 `/v1` 也可以），API Key 填第 3 步的 sk。

调用方只拿得到中继的 sk，拿不到上游秘钥。数据存在 `data/` 目录：`relay.db`（SQLite）和 `images/`（上游直接给 base64 时存的图片，过期自动删），备份 `relay.db` 即可。

## Docker 部署

服务器上需要 Docker 和 Compose 插件（`docker compose version` 能输出版本即可）。

```bash
# 把项目目录传到服务器，例如 /opt/nai-relay，然后：
cd /opt/nai-relay
cp .env.example .env        # 按需改 PORT、ADMIN_PASSWORD、UPSTREAM_KEY（可以直接填 NovelAI 的 pst- 令牌）
docker compose up -d --build
docker compose logs -f      # 看启动日志；没设 ADMIN_PASSWORD 时初始密码打印在这里
```

- `.env` 里的 `PORT` 同时是容器内监听端口和宿主机映射端口，API、图片链接、后台都在这一个端口。
- 数据在命名卷 `nai-relay-data`（容器内 `/app/data/relay.db`），重建、升级容器不会丢。
  备份：`docker compose cp nai-relay:/app/data/relay.db ./relay.db.bak`。
- 更新代码：传上新文件后再执行一次 `docker compose up -d --build`。
- 只走反代时，把 `docker-compose.yml` 里的端口映射改成 `127.0.0.1:端口:端口`，不让外网直接访问。

## 反向代理

中继只占一个端口，API（`/v1/...`）、图片链接（`/v1/img/...`）和后台（`/admin`）都在上面，反代时**整站**转发到
`http://127.0.0.1:<PORT>` 即可，不需要按路径拆开。Nginx 示例（`PORT=3000`）：

```nginx
server {
    listen 443 ssl;
    server_name img.example.com;
    # ssl_certificate / ssl_certificate_key ...

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # 聊天接口的流式输出和排队等待
        proxy_buffering off;
        proxy_read_timeout 330s;
        proxy_send_timeout 330s;
    }
}
```

只走反代时，可以在 `.env` 里设 `HOST=127.0.0.1`，不让外网直接访问端口。

**对外地址**（后台“设置”）决定返回的图片链接用哪个地址：

- 留空：用调用方访问本服务的地址。对方用 `http://服务器IP:3000` 调，图片链接就是 `http://服务器IP:3000/v1/img/...`；
  经上面的反代用域名调，就是 `https://img.example.com/v1/img/...`（靠 `Host` 和 `X-Forwarded-Proto` 头）。
- 填了：一律用填的地址。调用方从内网 IP 调、图片却要给外网用户看时填。

## 聊天生图 `/v1/chat/completions`

取**最后一条 user 消息的文字**当提示词，system 消息和历史消息都会忽略；这条消息里带了图片的，第一张当参考图做图生图（见“图生图”）。

```bash
curl http://127.0.0.1:3000/v1/chat/completions \
  -H "Authorization: Bearer $RELAY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "nai-diffusion-5-full",
    "stream": true,
    "messages": [{"role": "user", "content": "1girl, cat ears, cherry blossoms --ar 2:3 --no lowres, blurry"}]
  }'
```

回复内容形如 `![image](http://127.0.0.1:3000/v1/img/9cc8e8fc-e195-4cf3-be8b-8292f5cbce3b.png)`；`n` 大于 1 时多张图片用空行隔开。
后台把“聊天图片形式”改成内嵌 base64 后，会直接返回 `data:image/png;base64,...`。

流式请求时，若 8 秒内出图，直接一次性返回；排队更久时先开始 SSE，并定期发送空内容保活，防止客户端超时。
鉴权、额度、参数错误会按正常 HTTP 状态码返回；已经开始 SSE 后才失败的，以 `data: {"error": {...}}` 下发。

### 写在提示词里的参数

聊天客户端一般没法加自定义字段，可以把参数写在提示词末尾（写法类似 Midjourney）：

| 写法 | 作用 |
| --- | --- |
| `--ar 16:9` | 宽高比，换算成 NAI 尺寸（见下表） |
| `--size 832x1216` | 直接指定尺寸 |
| `--no lowres, blurry` / `--neg ...` | 负面提示词，取到行尾或下一个 `--参数` 为止 |
| `--steps 28` `--scale 5` `--seed 123` `--sampler k_euler` | NAI 扩展参数 |
| `--n 2` | 张数，1～4（逐张扣费） |
| `--strength 0.5` `--noise 0.1` | 图生图的重绘强度（0.01～0.99，默认 0.7）和加噪（0～0.99，默认 0） |
| 单独一行 `Negative prompt: ...` / `负面：...` | 该行之后全部作为负面提示词 |

不认识的 `--xxx` 会原样留在提示词里。请求体里的 `size`、`aspect_ratio`、`image_config.aspect_ratio`、`negative_prompt`、
`steps`、`scale`、`sampler`、`seed`、`n` 以及上游扩展字段也会转发，行内参数优先。

宽高比对应尺寸（总像素都不超过 1024×1024，不触发大图加价）：

| 比例 | 尺寸 | 比例 | 尺寸 |
| --- | --- | --- | --- |
| 1:1 | 1024x1024 | 4:5 / 5:4 | 896x1088 / 1088x896 |
| 2:3 / 3:2 | 832x1216 / 1216x832 | 9:16 / 16:9 | 768x1344 / 1344x768 |
| 3:4 / 4:3 | 896x1152 / 1152x896 | 9:21 / 21:9 | 640x1536 / 1536x640 |

其它比例按 1024×1024 的像素量等比换算，取 64 的倍数。

## 中文提示词

NAI 只认英文的 Danbooru 标签，直接写中文画不出想要的东西。中继在生图前会把提示词里的中文转成标签：

```
原神的可莉，开心地笑，背景是蒙德城
→ genshin impact, klee (genshin impact), happy, smile, mondstadt city

一个穿着白色水手服的双马尾少女在雨中奔跑，流着泪
→ 1girl, white serafuku, twintails, rain, running, tears
```

- 聊天和图片接口都生效。英文、`--ar` 等行内参数、NAI 的权重写法原样保留，只转换含中文的部分；
  `{{白色水手服}}`、`1.3::下雨::` 这种带权重的中文，权重会套回转出的标签上。
- 聊天回复里，图片下面会附上实际用的提示词（`> 提示词：…`），方便用户照着改；图片接口用 OpenAI 的 `revised_prompt` 字段返回。
- 认不出的中文会丢掉（NAI 看不懂中文），聊天回复里会列出“未识别”的部分；整句都认不出时返回 400，不浪费点数。
- 默认不转出 NSFW 标签。后台“设置 → 提词”里可以关掉中文转换、英文修正、回复里的提示词，或允许 NSFW。
- 后台调用日志里同时记录原文和转换后实际发出去的提示词。

转换做法：用逗号、顿号、空格隔开的词当独立概念，短词整体匹配，长句按词典分词（正向、逆向最大匹配），
去掉“的、在、穿着”这类停用词，再按“核心词 > 译名 > 同义词”挑标签，颜色和名词会组合（白色 + 水手服 → `white serafuku`），
提到作品时会用作品名帮角色消歧（命运石之门的助手 → `makise kurisu`）。这是词典匹配，不是大模型：
常见的人物、服装、动作、场景、作品和角色都认得，很口语或很抽象的描述可能认不全，这时可以去提词器里搜。

### 英文自动修正

英文标签也会顺便纠正（后台“设置 → 提词 → 英文自动修正”，默认开）：

| 写法 | 改成 | 说明 |
| --- | --- | --- |
| `valentines`、`ff7` | `valentine`、`final fantasy vii` | 别名和 Danbooru 已废弃的旧标签换成现行标签 |
| `twintail`、`cat-ears`、`multiple girl` | `twintails`、`cat ears`、`multiple girls` | 单复数、连字符写法统一 |
| `selafuku`、`school unifor`、`1gril`、`twintials` | `serafuku`、`school uniform`、`1girl`、`twintails` | 明显拼错的纠正（含相邻字母对调） |
| `long_hair`、`klee \(genshin impact\)` | `long hair`、`klee (genshin impact)` | 写法统一成 NAI 习惯（下划线换空格、去掉 SD 的 `\(` 转义），不算“修正” |

为了不改错，这些原样保留：英文句子（`a girl standing in the rain`）、`artist:`、`rating:` 这类带前缀的写法、
`masterpiece`、`best quality`、`very aesthetic` 等 NAI 质量词、画师名、认不出的词，以及本身就是正常英文单词的词
（`stars`、`spring`、`sharp` 不会因为和 `stairs`、`string`、`shark` 差一个字母被改掉）。
拼错只在 5 个字符以上、只差一两处、候选标签足够常用且没有同样接近的其它候选时才纠。

聊天回复里会多一行 `> 已修正：selafuku → serafuku，twintail → twintails`，提词器“转成标签”也会列出修正了哪些。

### AI 提示词优化

词典转换认不全很口语、很抽象的描述，这时可以接一个大模型，把整段描述改写成 NAI 提示词（构图、角色特征都会补全）。
在后台“AI 优化”页配置，默认关闭：

- **接口**：任意 OpenAI 兼容接口，填到 `/v1` 为止（中继请求 `地址/chat/completions`），再填 API Key 和模型名称。
  API Key 只在后台显示打码后的样子。
- **思考强度**：原样传给接口的 `reasoning_effort`，选“不传”就不带这个参数。DeepSeek 新模型默认先思考，改写提示词用不着，
  选 `none` 快一倍、成本省一半；要思考时不传 `temperature`（推理模型大多不认）。
  用 DeepSeek 推荐：地址 `https://api.deepseek.com`、模型 `deepseek-flash`、思考强度 `none`，一次优化 1～2 秒、不到 1 分钱。
- **什么时候优化**：关闭 / 自动（提示词里有中文或英文句子时才调，已经是英文标签的不调、不花钱，推荐）/ 每次都优化。
  调用方可以在提示词里写 `--ai` 强制优化、`--noai` 跳过，或在请求体里传 `"ai_optimize": true / false`。
- **对哪些模型生效**：所有模型，或者只对勾选的模型（按“模型”页的对外名称选）。没勾的模型不调 AI，调用方写 `--ai` 也不行，
  提示词照常走词典转换；提词器的“AI 优化”按钮也只对勾选的模型开放。后台的“测试”不受影响。
- **哪些调用密钥能用**：生成 sk 时可以不勾“AI 提示词优化”，之后也能在“密钥”页的列表里改。关掉的密钥出图时不调 AI，
  写 `--ai` 也不行，提示词照常走词典转换；拿它用提词器的“AI 优化”按钮会返回 403。默认开，按上面的设置走。
- **怎么改写**：本地词典先转一遍，结果作为参考一起发给模型，减少瞎编；模型写回来的标签再过一遍本地标签库（中文转换、旧标签和拼错纠正）。
  系统提示词可以在后台改，“恢复内置”回到默认。
- **内置系统提示词**借鉴 DanbooruSearchOnline 的 Anima 提示词规范（`config/prompt_formats.yaml`）里适用 NAI 的写法规则：
  标签顺序（人数 → 角色和作品 → 画师 → 外观 → 服装 → 表情 → 动作 → 取景 → 背景 → 光照 → 画风）、按场景复杂度控制标签数量、
  去掉近义重复、取景和标签一致（特写不留腿和鞋、上半身不留裙子和袜子）、不擅自加前景 / 天气 / 道具 / 人物、主体要被照亮、
  冲突检查（特写和全身、看镜头和背对等）、视线跟着动作、强调最多四个、多人物时人数精确且各自的特征分组不交叉。
  NAI 的写法单独处理：画师用 `artist:名字`、不加质量词（服务端会加）、权重用 NAI 的 `1.2::标签::` / `{标签}`。
- **按目标模型输出**：NAI4 及以后的模型能理解短句，AI 在标签后面最多再写三句英文，交代标签说不清的东西（人物在画面哪边、
  谁对谁做了什么、主体多大、怎么打光），多人物时每人一句定位再加一句互动（同样借鉴自该规范）；NAI3 只写标签。
- **让 AI 查标签库**（可选，默认关）：仿 DanbooruSearch 的 MCP 工具，用 function calling 让模型边查中继内置的标签库边写——
  `search_tags`（整段转标签 / 核对标签存不存在、纠正拼写和旧标签、列候选）、`get_related_tags`（常一起出现的标签，比如角色的标志性发色和服装）、
  `get_artist_recommendations`（只在用户要画风时用）。最多请求 5 轮、调 12 次工具，最后一轮不许再调工具、必须给出结果；
  每轮的 tokens 都累加计费，调用记录里能看到轮次和工具次数。模型或接口不支持工具调用时自动退回普通方式，并在记录里注明。
  更准，但一次优化要 2～5 轮，更慢也更费 tokens。
- **失败不影响出图**：接口报错、超时（30 秒）或没返回提示词时，自动退回词典转换的结果照常出图，原因记在 AI 调用记录里。
- 聊天回复里显示 `> 提示词（AI 优化）：…`，图片接口用 `revised_prompt` 返回；提词器的“AI 优化”按钮也走这里（要填调用密钥，每把密钥每分钟最多 20 次）。

**成本**：价格按“元 / 百万 tokens”填输入、输出、缓存读取、缓存创建四项（美元价格乘以汇率），每次调用按接口返回的 usage 计算：

```
成本 = 没命中缓存的输入 × 输入价 + 缓存读取 × 缓存读取价 + 缓存创建 × 缓存创建价 + 输出 × 输出价
```

缓存用量兼容 OpenAI 的 `prompt_tokens_details.cached_tokens`、DeepSeek 的 `prompt_cache_hit_tokens`、
Claude 转 OpenAI 格式时的 `cache_read_input_tokens` / `cache_creation_input_tokens`；输入按 OpenAI 口径（`prompt_tokens` 含缓存部分）。
失败的调用有 usage 也照算。

**闲时半价**：DeepSeek 官方按北京时间分时计价，工作日 9:00–12:00、14:00–18:00 是高峰，其它时间（含周末）半价。
勾选后价格填高峰价，闲时的调用自动按半价算成本（法定节假日调休不管）；别家接口不要勾。

在哪里看：

- “AI 优化”页：今日 / 累计的次数、各类 tokens 和成本，每次调用的明细（来源、调用密钥、模型、tokens、成本、耗时、原文和结果、错误），“测试”按钮可以先试通再打开。
- 概览：今日 / 累计的 AI 优化成本，以及**总成本 = NAI 扣点折合金额 + AI 成本**；近 14 天和按调用密钥的表里也有 AI 成本。
- 调用日志：走过 AI 优化的生图会标出模型、tokens 和这次的成本。

### 提词器 `/prompt`

公开页面（不需要登录、不花点数），让用户自己拼提示词：

- **中文描述转标签**：同上面的转换，转完可以去掉不要的再加入。
- **查标签**：中文按同义词和释义搜、英文按名称和别名前缀搜，按热度排序，可按通用 / 角色 / 作品 / 画师筛选，悬停看中文释义。
- **常用预设**：画质、人物、镜头、光影、场景、氛围、画风、服装、表情动作，一点就加。
- **已选标签**：拖动排序、`−` / `+` 调权重（NAI3 写成 `{}` `[]`，NAI4 及以上写成 `1.2::标签::`），撤销、清空、复制，
  质量词和负面提示词预设，收藏到本浏览器。
- **关联推荐 / 推荐画师**：按 Danbooru 上标签一起出现的统计（NPMI），推荐常一起用的标签和擅长画这些内容的画师（加入后是 `artist:名字`）。
- **试生成**：填调用密钥 sk，直接用当前提示词出图（会真实扣点）。拼好的已经是标签，出图时不再走一遍 AI 优化。

## 图片接口 `/v1/images/generations`

请求格式与 OpenAI Images 一致，NAI 扩展参数（`negative_prompt`、`steps`、`scale`、`sampler`、`seed` 等）放在 JSON 顶层：

- `response_format: "b64_json"` 真正返回 base64（NAI 上游只会给 URL，中继下载后转码）；
  模型名是 `gpt-image-*` 且没写 `response_format` 时，也按 OpenAI 的习惯返回 `b64_json`。
- 空 `prompt` 直接返回 400。上游不校验，空提示词也会出图扣点。
- `size: "auto"` 或缺省时，按 `aspect_ratio` 换算；也没有就用上游默认的 1024x1024。
- `url` 是中继的 UUID 图片链接。
- 提示词同样支持上面的行内参数。
- 带了 `image`（data URI、base64 或图片链接；也认 `images: [{ "image_url": "..." }]`）就是图生图，见下面的“图生图”。
  `/v1/images/edits` 也能用，参考图用 multipart 的 `image` / `image[]` 文件传。

## 图生图

四个出图接口都能图生图，参考图这样给：

| 接口 | 参考图 |
| --- | --- |
| `/v1/chat/completions` | 最后一条 user 消息里的第一张图：OpenAI 的 `image_url`、Responses 的 `input_image`、Anthropic 的 `image`（base64 或 url） |
| `/v1/images/generations` | 请求体的 `image`（数组取第一张），或者 `images: [{ "image_url": "..." }]` |
| `/v1/images/edits` | OpenAI 的图片编辑接口：multipart 里的 `image` / `image[]` 文件，或者 JSON 里和上面一样的 `image` / `images` |
| `/ai/generate-image` | 照官方：`action: "img2img"`，`parameters.image` 是 base64；网页端 V5 的 multipart 里图片单独一部分，`parameters.image` 写那一部分的名字 |

```bash
curl http://127.0.0.1:3000/v1/images/edits \
  -H "Authorization: Bearer $RELAY_KEY" \
  -F model=nai-diffusion-4-5-full -F 'prompt=1girl, watercolor' -F strength=0.5 \
  -F image=@photo.jpg
```

- 参考图支持 PNG、JPEG（包括渐进式 JPEG，手机照片按 EXIF 方向转正），最大 15 MB、2400 万像素；WebP、GIF 请先转成 PNG 或 JPEG。
  可以给 data URI、裸 base64 或图片链接；中继自己出的图的链接（`/v1/img/<uuid>.png`）直接从库里取，可以拿上一张接着改。
- 链接由中继去下载（20 秒超时、最多跳转 3 次，调用方断开就不下了）。解析出来是本机、内网、链路本地（包括云服务器的元数据地址
  `169.254.169.254`）的一律不连，IPv6 里内嵌这些地址的写法（映射地址、NAT64、6to4）也拦；连接时才检查，换 DNS 也绕不过去，防止有人借中继探内网。
- `strength` 是重绘强度（0.01～0.99，默认 0.7，越大和原图差得越多），`noise` 是加噪（0～0.99，默认 0）。写在请求体顶层，
  或者提示词里的 `--strength 0.5` / `--noise 0.1`；NovelAI 格式写在 `parameters` 里。和官网一样，图生图不开 SMEA。
- 出图尺寸：写了就用写的（`size`、`--ar`、`--size`、NovelAI 格式的 `width` / `height`），没写按参考图的比例出约 1024×1024 的（比如 2:3 的图出 832x1216）。
  官方要求参考图和出图一样大，中继把参考图**等比缩放、居中裁掉多出来的部分**，比例不一样时边上会被裁掉一些。出图上限压了尺寸的按压完的尺寸缩放。
- **只有 NovelAI 格式的上游能出**：类型是“NovelAI 官方”的秘钥（官方的 `pst-` 令牌，或者兼容官方接口的反代、中转站）。
  OpenAI 兼容上游的 `/images/generations` 没有图生图，图生图请求不会发给它们；一把能接的都没有时返回 400 `img2img_unsupported`。
- **图生图要花 Anlas**，不在 Opus 的免费范围里：大约是同尺寸文生图的价格乘重绘强度，每张至少 2。所以开着“只出免费图”的官方秘钥不接图生图，
  能接的秘钥都开着它时返回 400 `img2img_not_free`。要用官方秘钥图生图，在它的“出图上限”里关掉“只出免费图”（面积、步数、张数上限照样管着）。
- 开着“回复里附提示词”时，聊天回复多一行 `> 图生图：参考图 1200x1800 → 832x1216，重绘强度 0.7`；
  后台的调用日志和排队列表里，图生图请求的提示词前面标着“图生图 0.7”（重绘强度）。
- 不支持：局部重绘（`mask`、NovelAI 的 `infill`）、Vibe Transfer、角色参考、ControlNet，这类请求返回 400。
- 处理顺序：先查调用密钥的额度、有没有上游接得了，再读参考图（只看文件头），然后在单独的图片线程里解码、缩放
  （1200 万像素的照片大约 1 秒，不会卡住别的请求），都好了才调 AI 优化、排队等上游秘钥——缩放时不占着秘钥。
  文件头没问题但数据坏了的图在缩放时报 400 `invalid_image`，调用日志里记一条失败。
- 图片线程最多 3 个（按 CPU 核数），每个一次处理一张；排队超过 32 张返回 503 `image_busy`，调用方断开了还没开始处理的直接去掉，
  单张处理超过 30 秒算失败。解压炸弹、故意拖慢解码的畸形 JPEG 会很快被拒掉。同一个请求换秘钥重试时不重复缩放。

## NovelAI 官方格式 `/ai/generate-image`

给只会调 NovelAI 官方接口、但能改接口地址的客户端（各种 NAI 插件、脚本、SDK）用：接口地址填中继的根地址
`http://<服务器IP>:3000`（`/v1/ai/generate-image` 也认），API Key / Token 填中继的调用 sk（`Authorization: Bearer sk-...`）。

- 请求体和官方一样：`{ input, model, action, parameters: {...} }`，`action` 支持 `generate`（文生图）和 `img2img`（图生图，见上面的“图生图”）；
  也认官方网页端 V5 用的 multipart（JSON 放在 `request` 部分，图片各占一部分）。
- 默认返回 ZIP（`image_0.png`、`image_1.png` …），和官方一样；请求头 `Accept` 只写 `application/json` 时，
  按官方文档返回 `{ "images": [{ "image": "<base64>", "index": 0, "seed": 123 }] }`。
- 错误也是官方的样子 `{ "statusCode": 400, "message": "..." }`；调用 sk 额度用完返回 402（对应官方的 Anlas 不足）。
- `GET /user/subscription` 按 Opus 回，Anlas 填这把调用 sk 剩下的额度张数（不限额度时是 999999），客户端连接检查能通过。
- 客户端已经按网页端拼好质量词和负面预设，中继不再重复拼；`parameters` 里的多角色（`v4_prompt.caption.char_captions`、`characterPrompts`）、
  `cfg_rescale`、`noise_schedule`、`ucPreset` 等原样带给 NovelAI 官方上游。上游是 OpenAI 兼容的时，只转提示词、负面、尺寸、张数、步数、
  引导、采样器、种子这些通用参数。
- 模型映射、中文转标签、AI 优化、调用额度、记账和多上游轮询都和另外两个接口一样，后台日志里接口记为“NovelAI”。
- 局部重绘和参考类的功能不转：`action` 是 `infill`，或带了 `mask`、Vibe（`reference_image_multiple`）、角色参考
  （`director_reference_images`）的请求返回 400。

```bash
curl http://127.0.0.1:3000/ai/generate-image \
  -H "Authorization: Bearer $RELAY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"input": "1girl, smile", "model": "nai-diffusion-4-5-full", "action": "generate",
       "parameters": {"width": 832, "height": 1216, "steps": 28, "scale": 5, "n_samples": 1}}' \
  -o images.zip
```

## 模型

请求里的 `model` 按后台“模型”页解析：

- 写的是已启用的模型（对外名称）→ 调它对应的上游模型。对外名称可以自定义，比如 `anime-v5` → `nai-diffusion-5-full`。
- 没写，或写的是 `dall-e-3`、`gpt-image-1`、`gemini-*-image` 这类别家模型名 → 用默认模型。
- 写了 `nai-*` 但没添加或已停用 → 400，避免拼错名字却悄悄换了模型。

“从上游获取”会把各个上游接口地址的 `/models` 合在一起列出来（接了多个上游时标出每个模型来自哪里；NovelAI 官方没有这个接口，列内置的官方模型），
勾选即可添加；首次启动自带 NAI5 的两个模型。
某个模型只有部分上游有时，在“上游秘钥”页给秘钥填上“支持的模型”，见下面“上游秘钥”。

## 图片链接

上游返回的图片地址只存在数据库里，对外返回 `<对外地址>/v1/img/<UUID>.png`，访问时由中继去上游拉取再返回。
上游不给链接、直接给 `b64_json` 的（或者 `url` 里放的是 data URI），图片存到数据目录的 `images/` 下，同样给 UUID 链接。
链接有效期在后台设置（默认 7 天，修改只影响之后生成的图片），过期的记录和本地图片每小时清理，过期后访问返回 404。

链接用哪个地址见上面“反向代理”里的“对外地址”。

## 上游秘钥

在后台“上游秘钥”页管理，可以一次贴多把（一行一个）：

- **类型**：每把秘钥是“OpenAI 兼容”或“NovelAI 官方”，两种可以混着接。
- **接口地址**：每把秘钥带自己的接口地址，可以接好几个不同的上游。OpenAI 兼容的填到 `/v1` 为止，
  中继请求“地址/images/generations”出图、“地址/models”取模型列表；误填成完整接口地址的会自动截掉。
  中继先要图片链接（`response_format: "url"`），上游不认这个参数时自动去掉重发；上游给链接或 `b64_json` 都行。
- **NovelAI 官方**：秘钥填持久令牌 `pst-...`，接口地址留空就是 `https://image.novelai.net`（自建反代时填反代地址）。
  中继把请求转成官方格式调 `地址/ai/generate-image`，从返回的 ZIP 里取出图片：
  - 参数照官方网页端：默认 28 步、引导 5、`k_euler_ancestral` + `karras`，尺寸取到 64 的倍数（没给时 1024x1024），
    NAI4 以后的模型带 `v4_prompt`，V5 用 `params_version: 4` 和网页端一样的 multipart 请求；`nai-diffusion-5-full-medium` 固定 14 步。
  - 官方服务端不加质量词和负面预设，是网页端拼进提示词的。从聊天、图片接口进来的请求由中继照网页端默认拼上
    （各代模型的“质量词”和“Heavy”负面预设，提示词里有 `nsfw` 时负面预设里的 `nsfw` 去掉）；请求体里可以传
    `"qualityToggle": false` 不加质量词、`"ucPreset": 0～4` 换负面预设，`cfg_rescale`、`sm`、`sm_dyn`（只有 NAI3）也会转。
    从 NovelAI 格式接口进来的请求客户端已经拼好，原样发。
  - 官方不让同一个账号同时生成多张（并发会 429），官方令牌的“并发”默认 1，超出的请求在号池里排队（见下面的“并发和排队”）。
  - 默认按“Opus 免费档”出图、并且“只出免费图”，不会花 Anlas，见下面的“出图上限和只出免费图”。
  - 图生图只有这种上游能出，参考图由中继缩放好放进请求（见“图生图”）。
  - “拉取模型”列出内置的官方模型，同时查这把令牌的套餐、Anlas 余额和 Opus 用量条（`地址/user/subscription`），也顺便验证令牌能不能用。
  - 官方返回的 401（令牌失效）、402（Anlas 不足 / 没订阅）、429（同一账号在别处正在出图）按下面的“失败切换”处理。
  - 注意 NovelAI 的服务条款：生图请求必须由人发起，不能自动化刷请求；账号共享给别人用也可能违反条款，自己斟酌。
- **支持的模型**：上游模型名，请求这些模型时才会轮到这把秘钥；留空表示什么模型都接。
  点“拉取模型”会用这个接口地址和秘钥查上游的 `/models`，列出来打勾就行（添加时用填的地址和第一把秘钥，列表里的秘钥也能单独拉取）；也可以手填，逗号分隔。
  接了好几个上游、各家模型不一样时，每把都填上，免得请求被发到没有这个模型的上游。
- **优先级**：数字大的先用，默认 0，可以填负数。同优先级的秘钥轮流用；高优先级的都在忙（满了并发）、冷却中、失败了，
  或者不接这个请求（见“只出免费图”）时，才用低优先级的。和 new-api 的渠道优先级一样是“数字越大越先选中”。
- **轮询**：在同优先级、支持这个模型的秘钥里，每次请求从下一把开始，按顺序轮流用；满了的跳过（见下面的“并发和排队”）。
- **失败切换**：某把秘钥被上游拒绝时自动换下一把重试——401（失效）、402（点数不足）、403（不允许该模型）、429（限流）。
  这几种上游没有出图也没有扣点。这把秘钥冷却 10 分钟（429 冷却 1 分钟）后再参与轮询，后台显示冷却状态和最近一次错误。
  上游说没有这个模型（404 或 `model_not_found`）也换下一把，但不冷却，它接别的模型照样正常。
  超时和上游 5xx **不**换秘钥重试，因为上游可能已经出图扣点，重试会重复扣费。
- **所属账号**：有的上游按账号分档计价（比如每个账号每天前若干张便宜，网站和这个账号下所有 sk 合并计数），
  同一个上游账号的多把秘钥填同一个账号名，估算才准；不填则每把秘钥单独算。
- **查余额**：OpenAI 兼容的上游没有统一的余额接口，余额请登录各个上游网站查看。NovelAI 官方令牌在列表的“状态”里直接显示
  套餐、Anlas 余额和 NAI5 免费额度（Opus 用量条），中继每 5 分钟查一次，点“刷新”立刻查。
  后台按上游秘钥显示的是经过本中继的估算用量。

### 出图上限和只出免费图

防止有人用官方秘钥出大图、加步数、一次出多张，把账号的 Anlas 花掉。在“上游秘钥”页每把秘钥的“出图上限”里点“改”设置：

- **最大面积**（宽×高，可以写成 `1024x1024`）、**最多步数**、**每次最多张数**，0 表示不限。超出的**压到上限照常出图**，不报错：
  尺寸等比缩小、宽高取 64 的倍数（比如 1536x1024 → 1216x832），步数、张数取上限。聊天回复里会多一行
  `> 已按出图上限调整：尺寸 1536x1024 → 1216x832`，调用日志的尺寸下面也写着改了什么，能看出谁在要大图。
  压的是最终发出去的参数：请求体、提示词里的 `--size` / `--steps` / `--n`、NovelAI 格式的 `parameters`，哪条路都绕不过去。
- NovelAI 官方秘钥默认 **Opus 免费档**：1024×1024 以内、28 步以内、一次 1 张，Opus 订阅出这样的图不花 Anlas。
  `nai-diffusion-5-full-medium` 固定 14 步，不受步数上限影响。OpenAI 兼容的秘钥默认不限；设了的话只压请求里写了的参数
  （没写步数就是上游自己的默认值，中继不知道是多少，不替它填），没写尺寸按 1024×1024 算。
- **只出免费图**（只有官方秘钥有，新加的官方秘钥默认开）：中继照官网网页端的计价算这次要花多少 Anlas，要花就不发给这把秘钥，
  换别的秘钥；都不行时，是账号那边的原因（用量条用完、不是 Opus、状态查不到）返回 503“免费额度暂时用完了”，
  是请求本身超出免费范围（上限放开了、又要大图或多张）返回 400 `outside_free_range`。为什么有了上限还要它：
  - NAI5 的免费出图要扣 Opus 的用量条，**用量条用完后 NAI5 每张都收 Anlas**（普通尺寸约 26～30），上限管不住。
    这时只出免费图的秘钥不再接 NAI5 的请求（NAI4.5 及以前的照常免费出），返回的提示会建议换 NAI4.5。
    用量条是一张张扣的，所以只出免费图的秘钥**每出一张 NAI5 前**都要确认手上的用量条够新：查询超过一分钟的、
    或者用量条剩得不多（5% 以下，5% 大约 80 多张）又是上一张出完之前查的，就占着这把秘钥先查一次再决定。
    账号主人同时在网页上用掉用量条的话，最多有一分钟的空档。
  - 账号不是 Opus（或订阅过期）时每张都收 Anlas，开着它的秘钥不接请求。
  - 账号状态靠查 `地址/user/subscription`：启动时、之后每 5 分钟、每次出图后各查一次，查失败 20 秒后重试。
    从没查到过、超过 30 分钟没查成功、或者**最近一次查询失败**，就当不知道，开着它的秘钥不接请求（宁可不出图也不花 Anlas）。
    自建反代没有这个接口的话，要么关掉“只出免费图”，要么反代把它也转过去；列表的“状态”里会写查询失败的原因。
  - 要用官方秘钥出要花 Anlas 的图，关掉它就行；单张超过 140 Anlas 的（官网网页端也不让这么出）无论开没开都不发，返回 400。
  - 图生图每张都要花 Anlas，开着它的秘钥不接图生图（见“图生图”）。
- 已经开始排队的请求，轮到时按当时的账号状态再算一次，不接就继续等别的秘钥。
- 免费额度用完、参数太大这类错误在调 AI 提示词优化**之前**就返回，不白花 AI 的钱，流式聊天也会按正常 HTTP 状态码报错。
- 调用密钥的额度按**实际会出的张数**算：官方秘钥一次只出 1 张的话，要 4 张也只占 1 张额度；正在出图、排队中的也算进去，
  一把 sk 同时发很多请求不会一起越过额度。
- 把秘钥的类型改成 NovelAI 官方时，没一起改的并发、出图上限、只出免费图按官方的默认值来；改回 OpenAI 兼容会关掉只出免费图。
- 从上一版升级：已有的官方秘钥套上 Opus 免费档；接官方地址（`https://image.novelai.net`）的打开只出免费图，
  接自建反代的不自动打开（反代不一定转发 `/user/subscription`），需要的话在“改”里手动打开。

### 并发和排队

每把上游秘钥有个“并发”：同时最多出几张图（一次请求算一个，`n` 张也只占一个）。添加时留空的话，NovelAI 官方是 1
（官方不让同一账号并发），OpenAI 兼容是 0（不限，和以前一样）；在“上游秘钥”页的列表里随时能改，改了立刻生效。

- 能接这个模型的秘钥都满了时，请求不报错，在中继的号池里**排队**，有秘钥空出来就按到达顺序发下一个。
  排在前面的模型没空位，不挡后面别的模型的请求。
- 某把秘钥失败换下一把（见上面的“失败切换”）时，如果下一把正忙，请求回到原来的位次继续等，不会排到最后。
- 冷却中的秘钥只在没有别的秘钥可用时才用。
- 排队最长等多久（默认 300 秒）、最多排多少个（默认 100，0 不限）在后台“设置 → 排队”里改，超出返回 503。
  流式聊天在排队时照样每 8 秒发保活；非流式的客户端自己的超时可能更短，排队久了可能先断开。
- 调用方断开连接的请求自动移出队列，不会再发给上游扣点。
- 队列只在内存里，中继重启时排队中的请求随连接一起断开。

后台“排队”页**实时**（每秒刷新）显示号池：每把秘钥正在出图 / 并发上限、正在出图的请求（用哪把秘钥、哪个调用密钥、出图多久、排队了多久）、
排队中的请求（位次、已等多久、能分到哪些上游）。顶部可以选只看 NovelAI 官方、OpenAI 兼容或某一把秘钥。
调用日志里排队超过 1 秒的请求会标出排队了多久。

## 不暴露上游

返回给调用方的内容里不出现任何一个上游的域名、图片地址等信息：

- **图片链接**：只有 UUID，图片由中继代拉，只回自己的响应头（不透传上游的 `Server`、`ETag` 等）。
- **错误信息**：只转 `message` / `type` / `code`，`message` 里的网址、域名（包括每个上游接口地址的域名）、邮箱、IP 和后台设置的隐藏词会替换成 `***`，
  `error.url` 等其它字段丢弃。上游原始错误只写进后台调用日志，方便管理员排查。
- **上游秘钥都不可用**（失效、点数不足、没开通模型）：调用方只看到“生图失败：服务暂时不可用，请联系管理员”，不会误以为是自己的 sk 有问题。
- **提示图**：有的上游点数不足、额度耗尽时会照样回 HTTP 200，图片却是 `/img/error/` 下的提示图（如 `balance-insufficient-….png`）。
  中继认出来后不把提示图给调用方，按生图失败处理（换下一把秘钥、这把冷却，日志里记失败、不计扣点）；批量里混着提示图的只留真图。
- **模型列表**：只给对外名称，`owned_by` 统一为 `novelai`。

图片本身的 PNG 元数据是 NovelAI 生成时自带的（提示词、种子、采样参数等），不含上游站点信息，原样保留。

## 上游扣点

**扣点是估算值**，按“模型”页的计价规则计算：

- 每张基础点数；“每日第 N 张后”涨价，按北京时间零点重置，同一个上游账号的同一代模型（如 NAI5 精选版和完整版）合并计数，0 表示不分档；
- 大图（总像素超过 1024×1024）每张另加点数；失败的调用按退点计 0。

各家上游价格不一样，新添加的模型计价都是 0（不估算），按自己用的上游在“模型”页填；按张收费的，把每张的价格折成点数填。

NovelAI 官方秘钥出的图另外按官网网页端的计价**估算 Anlas**（和“扣点”分开记）：按实际发出去的尺寸、步数、张数和 SMEA，
NAI5 乘 1.5，Opus 账号在 1024×1024、28 步以内时一次请求的第一张免费（NAI5 还要用量条没用完）。调用日志、上游秘钥列表、概览里都有。
这是网页端显示的价格，不是 NovelAI 的账单，实际以账号的 Anlas 余额为准（列表里能看到每 5 分钟查到的余额）。

后台“每点价格”把点数折算成金额，默认 0（不折算），按自己的充值价格填。
估算只统计经过本中继的调用，上游账号在网页上的用量不计入，实际以上游账号流水为准。

## 环境变量

见 [.env.example](.env.example)：

| 变量 | 说明 |
| --- | --- |
| `PORT` / `HOST` | 监听端口和地址，默认 `0.0.0.0:3000`（所有接口和后台共用这一个端口） |
| `DATA_DIR` | 数据目录，默认 `./data` |
| `ADMIN_PASSWORD` | 设置后每次启动都把后台密码重置成它；不设则沿用后台里改的密码 |
| `UPSTREAM_TIMEOUT_MS` | 上游超时，默认 300000（含排队时间） |
| `UPSTREAM_KEY` / `UPSTREAM_BASE` | 首次启动导入的上游秘钥（多把用逗号分隔）和它们的接口地址；之后在后台“上游秘钥”页管理。`pst-` 开头的按 NovelAI 官方导入，`UPSTREAM_BASE` 可以不填；OpenAI 兼容的要填到 `/v1`。从只有一个上游的旧版升级时，库里没有接口地址的秘钥自动补上 `UPSTREAM_BASE` |
| `PUBLIC_BASE_URL` | 只作为首次启动的初值，之后以后台“设置”为准 |

## 注意

- 每次 chat 请求都会真实生图扣点。部分客户端会用同一个模型自动“生成话题标题”，这也会触发生图，建议在客户端里把标题生成换成别的模型或关掉。
- 图生图只有 NovelAI 格式的上游能出，而且要花 Anlas（见“图生图”）；局部重绘、Vibe、角色参考都不转，返回 400。
- 超时（默认 300 秒）后可能已经生成并扣点，先看后台调用日志，避免重复提交。
- 后台登录状态只存在内存里，中继重启后需要重新登录。
